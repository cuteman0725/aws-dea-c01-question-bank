兩種 log 要分開過濾，先把格式改成 JSON

題目要 Lambda 的 App logs 只顯示 ERROR、System logs 只顯示 WARN。四個選項裡只有 C 做得到：把 Log format 設成 JSON。

題目

要怎麼讓兩種 log 各自只顯示指定層級？

一支用 managed runtime 執行的 Lambda 函式，log 都寫進 CloudWatch Logs。現在要：

只顯示 ERROR

只顯示 WARN

選項（點一下，到動態圖看效果）

題目與選項依 Notion 題庫筆記的題意整理，不是英文原文。

正確答案

C

把 Lambda 函式的 Log format 設成 JSON

JSON 格式才有兩個各自獨立的門檻：Application log level 設 ERROR、System log level 設 WARN。預設的 Text 格式不能做層級過濾。

動態架構圖

切換選項，看 log 怎麼流進 CloudWatch

原狀 Log format 是預設的 Text，兩個門檻都鎖住，每一種層級的 log 都直接進 CloudWatch。

理由

為什麼是 C：三件事接起來就懂

  1. 1

    兩種 log，來源不同

    </>App logs

    Application logs，你的程式碼印出來的

    logger.error("連線失敗") ERROR

    System logs

    Lambda 平台自己產生的事件

    • INFOstart
    • INFOreport
    • WARNlogsDropped

    程式碼只管得到 App logs；System logs 要在 Lambda 的日誌設定裡調。所以 B 只對一半。

  2. 2

    設定的是「門檻」

    ↑ 越往上越嚴重、筆數越少

    App 門檻 ERROR

    FATAL留下
    ERROR留下
    門檻
    WARN擋下
    INFO擋下
    DEBUG擋下
    TRACE擋下

    System 門檻 WARN

    WARN留下
    門檻
    INFO擋下
    DEBUG擋下

    選一個層級，就是「這一級和更嚴重的」會留下，所以 App 選 ERROR 時 FATAL 也會留下。兩種 log 的預設門檻都是 INFO。

  3. 3

    這兩個門檻，只有 JSON 格式才能設

    Text[ERROR] 2026-10-09T11:55:02Z 資料庫連線失敗
    JSON{"timestamp":"…", "level":"ERROR", "message":"資料庫連線失敗"}

    Text 只是一行字；JSON 讓每筆 log 都有固定的 level 欄位，Lambda 才能照門檻過濾。AWS 官方文件寫明：要用 log-level filtering，函式必須設成 JSON log format，而 managed runtime 預設是 Text。用 AWS 支援的 runtime 和 logging 方法時，不用改程式碼。

    主控台設定示意Monitoring and operations tools → Logging configuration → Edit

    Log formatTextJSON
    Application log levelERROR
    System log levelWARN
    用 AWS CLI 一個指令設定
    aws lambda update-function-configuration \
  --function-name my-function \
  --logging-config LogFormat=JSON,ApplicationLogLevel=ERROR,SystemLogLevel=WARN

    把 my-function 換成你的函式名稱。

其他選項卡在哪

  • A
    加 IAM 權限權限管「能不能寫進 CloudWatch」，不管「寫哪些層級」。
  • B
    程式碼設 ERROR只管得到自己印的 App logs；System logs 照樣全部進來。
  • D
    換 log group只換存放位置，沒有任何過濾。

一句話記住

看到「App logs、System logs 要設不同層級」，就想到先開 JSON log format（選 C）。
